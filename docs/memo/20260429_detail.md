

### 1. デザインコンセプト：ドリルダウン・インスペクター

単なる進捗確認だけでなく、**「その日に誰が（提出者）、どの株を（発行者）、どれくらい保有したか（割合）」**を即座に確認できる構成にします。

*   **Step 1: 月別タイル**（進捗の全体把握）
*   **Step 2: 日別リスト**（特定日の成功/失敗の把握）
*   **Step 3: データ・プレビュー（追加機能）**：日別リストの「完了数」をクリックすると、その日に取り込まれた `documents` ＋ `ownership_reports` の内容をモーダルで表示します。

---

### 2. 追加するクエリのロジック

特定の日付（例: `2026-05-01`）にインポートされた詳細データを取得するための結合クエリです。

```sql
-- 特定日のインポート済み大量保有報告書一覧
SELECT 
    d.doc_id,
    d.submit_datetime,
    d.submitter_name,
    d.issuer_name,
    o.obligation_date,
    o.holding_ratio,
    o.prev_holding_ratio,
    (o.holding_ratio - o.prev_holding_ratio) as ratio_diff
FROM documents d
JOIN ownership_reports o ON d.doc_id = o.doc_id
WHERE DATE(d.submit_datetime) = '2026-05-01'
  AND d.doc_type_code = '350' -- 大量保有報告書
ORDER BY d.submit_datetime DESC;
```

### 3. フロントエンド実装コード

Next.js (App Router) + Tailwind CSS + Lucide Icons を想定した実装案です。

#### A. メインページ (`src/app/daily_status/page.tsx`)
サーバーコンポーネントで初期データを取得します。

```tsx
import { DailyStatusDashboard } from "@/components/pages/daily_status";
import { db } from "@/lib/db";

export default async function Page() {
  // 初期の年・月データを取得（例: 2026年4月）
  // 実際にはURLクエリパラメータ等で制御
  const dailyStats = await db.execute({
    sql: `SELECT * FROM import_daily_status 
          WHERE target_date LIKE '2026-04-%' 
          ORDER BY target_date ASC`,
    args: []
  });

  return (
    <div className="container mx-auto py-8">
      <DailyStatusDashboard initialData={dailyStats.rows} />
    </div>
  );
}
```

### プロのエンジニアとしての設計ポイント

1.  **解析データの重要性**:
    *   `ownership_reports` テーブルの `holding_ratio` (保有割合) と `prev_holding_ratio` (前回の割合) を引き算して **「増減 (diff)」** を表示させると、インポートが正しく行われたかの検証だけでなく、投資判断ツールとしての価値が一気に高まります。

2.  **UXの工夫**:
    *   `status = 'failed'` の行には `error_message` をツールチップやポップオーバーで表示するようにすると、保守性が向上します。

3.  **パフォーマンス**:
    *   詳細データ（ドリルダウン部分）は、ページロード時にすべて読み込むのではなく、**「データを閲覧」ボタンを押した時に `Server Actions` または `client-side fetch` で Turso にクエリを投げる**構成にすると、ページ初期表示が軽くなります。
