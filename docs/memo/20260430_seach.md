「クジラ（投資家）」を探すための検索画面は、このSaaSにおいて**分析の入り口**となる非常に重要なページです。

`edinet_codes`（法人・個人）と `fund_codes`（投資信託など）は属性が異なるため、**「一つの検索窓で両方を検索でき、かつ結果をタブやカテゴリーで分かりやすく分ける」**インターフェースを提案します。

---

### 1. 検索画面のコンセプト：ユニバーサル・サーチ
日本語名、英語名、証券コード、ヨミ、どこからでもヒットするようにし、結果を「エンティティ（法人）」と「ファンド」で整理して表示します。

#### 検索対象ロジック (SQLイメージ)
```sql
-- 法人検索
SELECT 'entity' as type, edinet_code as code, submitter_name as name, industry, sec_code 
FROM edinet_codes 
WHERE submitter_name LIKE ? OR submitter_name_en LIKE ? OR submitter_name_kana LIKE ? OR sec_code LIKE ?

-- ファンド検索
SELECT 'fund' as type, fund_code as code, fund_name as name, category, issuer_name 
FROM fund_codes 
WHERE fund_name LIKE ? OR fund_name_kana LIKE ? OR issuer_name LIKE ?
```

### 3. プロのフロントエンドエンジニアとしての実装アドバイス

1.  **ハイライト表示 (Highlighting)**:
    検索ワード（例：「しんきん」）に一致した部分を `<mark>` タグや太字で強調するように実装すると、なぜその結果が出たのかユーザーが直感的に理解できます。

2.  **サジェスト機能 (Autocomplete)**:
    入力中にリアルタイムで候補を出す仕組みが望ましいです。Next.jsであれば、`debounce`（入力をやめてから300ms後に検索実行）を入れることで、Tursoへのリクエスト回数を抑えつつ快適な操作感を提供できます。

3.  **証券コードの正規化**:
    ユーザーが「1376」と入力しても「13760」と入力してもヒットするように、検索ロジック側で末尾0を考慮した曖昧検索（`LIKE '1376%'`）にするのが親切です。

4.  **画面遷移の設計**:
    *   法人カードをクリック → その投資家の「保有銘柄一覧（Whale Portfolio）」へ。
    *   ファンドカードをクリック → そのファンドの「組入銘柄分析」へ。
