### 1. なぜ5桁なのか？
日本の証券コード（新証券コード）は本来5桁で定義されています。
*   **前の4桁**: 私たちが普段目にする「銘柄コード（例: 7203）」です。
*   **最後の1桁（5番目）**: 通常の「普通株式」の場合は **必ず `0`** になります。

EDINET APIやコードリストから取得できる証券コードが `72030` となっているのは、システム上の正式な桁数に従っているためです。

### 2. 「Stock Whale Radar」実装上の注意点

この証券コードを扱う際、エンジニアとして以下の2点を考慮する必要があります。

#### ① yFinance 等の外部APIとの連携
yFinance や他の株価API（株探など）を利用する場合、5桁のままではエラーになります。
*   **変換ルール**: `72030` → 末尾を削って `7203` にし、市場コードを付ける（例: `7203.T`）。

#### ② 「提出者」と「発行者」の証券コードの混同
ここが「Stock Whale Radar」において最も重要な点です。

*   **提出者（Submitter）の証券コード**:
    *   「クジラ（投資家）」自身が上場企業（例：ソフトバンクグループなど）である場合に値が入ります。
    *   もし個人投資家や非上場の資産運用会社であれば、ここは**空欄（NULL）**になります。
*   **発行者（Issuer）の証券コード**:
    *   「クジラが買った対象」の企業（例：トヨタ自動車）のコードです。
    *   あなたが `ownership_reports` テーブルで最も頻繁に利用し、株価チャートを表示させるのはこちらの方です。

### 3. フロントエンドでの処理コード例 (TypeScript)

フロントエンドで表示する際に、5桁を4桁に変換するユーティリティ関数を作っておくと便利です。

```typescript
/**
 * EDINET形式の5桁証券コードを4桁に変換する
 * 例: "72030" -> "7203"
 */
export const formatSecCode = (edinetSecCode: string | null | undefined): string => {
  if (!edinetSecCode) return "";
  
  // 5桁ある場合は、先頭の4桁を取得
  if (edinetSecCode.length === 5) {
    return edinetSecCode.substring(0, 4);
  }
  
  return edinetSecCode;
};

/**
 * yFinance用のティッカーシンボルを生成する
 * 例: "72030" -> "7203.T"
 */
export const toYFinanceTicker = (edinetSecCode: string): string => {
  const code4 = formatSecCode(edinetSecCode);
  return code4 ? `${code4}.T` : "";
};
```

### まとめ
*   **証券コード 5桁（末尾0）**: EDINETの正式なデータ形式。
*   **証券コード 4桁**: 私たちが日常的に使う形式。
*   **DB保存**: データの整合性を保つため、**一旦5桁のまま保存**し、表示やAPI連携の際に上記のような関数で変換するのが「プロの保守性の高い設計」です。

また、提出者種別が `1`（個人）の場合は、証券コードはほぼ確実に空になるため、UI上では「-」や「非上場」と表示するロジックを組むのが良いでしょう。
