NVIDIA NIM（build.nvidia.com）を利用して Roo Code でコーディングする場合、2026年現在のラインナップでは以下のモデルが特におすすめです。

NIM は OpenAI 互換 API を提供しているため、Roo Code の設定で `OpenAI Compatible` を選択し、Base URL に `[https://integrate.api.nvidia.com/v1](https://integrate.api.nvidia.com/v1)` を指定することで利用できます。

---

### 1. 【最強のエージェント性能】 Llama-3.3-Nemotron-70B-Instruct

NVIDIA が Llama 3 をベースに独自カスタマイズしたモデルです。

* **特徴:** 特に「指示に従う能力（Steerability）」と「推論の正確性」において、Claude 3.5 Sonnet に匹敵するスコアを叩き出しています。
* **相性がいい理由:** Roo Code のような「自律型エージェント」がツール（ファイル操作・ターミナル）を呼び出す際の成功率が非常に高く、複雑な機能の実装でも「迷子」になりにくいです。

### 2. 【ロジカルな難問解決】 DeepSeek-R1 (NIM版)

「思考（Reasoning）プロセス」を可視化するモデルです。

* **特徴:** 実装前に「なぜその修正が必要か」を深く考え抜くため、数学的なアルゴリズムや複雑なデータ構造を扱う際に真価を発揮します。
* **相性がいい理由:** バグの原因が不明なときや、大規模なリファクタリングの「戦略」を立てる際に Roo Code に使わせると、非常に精度の高い修正案が出てきます。

### 3. 【超大規模プロジェクト用】 Nemotron-3-Super-120B

NVIDIA 独自のハイブリッドアーキテクチャ（Mamba + Transformer）を採用したモデルです。

* **特徴:** **最大 100万トークン** という広大なコンテキストを持ちつつ、レスポンスが非常に高速です。
* **相性がいい理由:** 既存のコードベースが非常に巨大で、Gemini 以外で全体を把握させたい場合の強力な選択肢になります。

---

### 目的別の使い分け例

| 状況 | 推奨モデル（NIM内） | 理由 |
| --- | --- | --- |
| **日常的な機能追加** | **Llama-3.3-Nemotron-70B** | 指示理解が正確で、ツール実行に失敗しにくい。 |
| **複雑なバグの特定** | **DeepSeek-R1** | 深い推論を行い、エッジケースまで考慮する。 |
| **巨大なコードの解析** | **Nemotron-3-Super-120B** | 100万トークンの文脈でプロジェクト全体を俯瞰。 |

---

### 設定時の注意点

1. **API Key:** NVIDIA Developer Program で発行した `nvapi-` から始まるキーを使用してください。
2. **Rate Limit:** NIM の無料枠は、エージェント（Roo Code）が自律的に連投すると制限（40 RPMなど）に掛かりやすいです。もし頻繁に止まる場合は、Roo Code の設定で「Max Iterations（最大反復回数）」を少し低めに設定して様子を見るのがコツです。

**アドバイス:**
まずは **Llama-3.3-Nemotron-70B** をメインに据えてみてください。現在の Google AI Studio (Gemini) と比較して、より「開発者らしい、簡潔で正確なコード」を書く傾向があることに気づくはずです。
