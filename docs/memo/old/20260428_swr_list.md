## 4. データ抽出ロジック（SQLイメージ）

株を指定して一覧を出すための結合クエリ案です。

```sql
SELECT 
  O.obligation_date,      -- 報告義務発生日
  D.submitter_name,       -- 投資家名
  O.holding_ratio,        -- 今回の保有割合
  O.prev_holding_ratio,   -- 前回の保有割合
  (O.holding_ratio - O.prev_holding_ratio) AS diff_ratio, -- 増減
  O.holding_purpose,      -- 保有目的
  D.doc_description,      -- 書類概要
  D.doc_id                -- 詳細へのキー
FROM ownership_reports O
JOIN documents D ON O.doc_id = D.doc_id
WHERE D.issuer_edinet_code = 'EXXXXX' -- 検索された発行者のコード
   OR D.sec_code = '72030'            -- 検索された証券コード
ORDER BY O.obligation_date DESC;
```

---

## 5. 仕様のポイント

### ① 投資家名の名寄せ
`submitter_edinet_code` をキーにすることで、投資家名が微妙に表記揺れ（例：「株式会社〇〇」と「(株)〇〇」）していても、同一の投資家としてグルーピングが可能です。

### ② 「義務発生日」と「提出日」の使い分け
* **義務発生日 (`obligation_date`)**: 株価に影響を与えた実質的な日付として、一覧の主軸（ソート順）にします。
* **提出日時 (`submit_datetime`)**: 実際に市場に情報が公開されたタイミングとして、詳細エリアに表示します。

### ③ 差分の可視化
`holding_ratio` と `prev_holding_ratio` の差分を計算し、**「買い増し（+）」なら赤、「売却（-）」なら青**で表示すると、投資家のスタンスが一目でわかります。

この構成をベースに、UIツール（FigmaやExcel等）で肉付けしていただければ、実用的な仕様書になるかと思います！

## 4. データ抽出ロジック（SQLイメージ）

特定の投資家に紐づく銘柄の動きを新しい順に取得します。

```sql
SELECT 
  O.obligation_date,
  D.issuer_name,          -- 発行会社名（株の名前）
  D.sec_code,             -- 証券コード
  O.holding_ratio,
  (O.holding_ratio - O.prev_holding_ratio) AS diff_ratio,
  O.holding_purpose,
  D.doc_id
FROM ownership_reports O
JOIN documents D ON O.doc_id = D.doc_id
WHERE D.submitter_edinet_code = 'E12345' -- 指定した投資家のコード
ORDER BY O.obligation_date DESC;
```

---

## 5. 仕様のポイント

### ① 「売却」の強調表示
投資家軸の画面では、新たに株を買った（新規・買い増し）情報だけでなく、**「いつその銘柄から撤退したか（保有割合が減少、または0%になったか）」**が投資戦略を読み解く重要な鍵となります。減少分は青文字や下向き矢印で強調します。

### ② 銘柄名へのリンク
「銘柄名」をクリックすると、前述の「銘柄別保有推移画面」へ遷移できるようにします。これにより「この投資家が売っている時に、他の投資家はどう動いているか？」という多角的な分析が可能になります。

### ③ 保有目的の変化
同じ銘柄でも、買い増しの過程で `holding_purpose` が「純投資」から「経営陣への助言・重要提案」などに変化した場合、アラートや強調表示を行うと、アクティビスト（物言う株主）の動向察知に役立ちます。
